# 포트폴리오 3페이지 — AI 네이티브 엔지니어링 적용기

---

## 페이지 콘셉트

**제목:** `AI와 함께 개발하기 — AI 네이티브 엔지니어링 적용`  
**부제:** _"AI를 도구로 쓰는 것을 넘어, AI가 팀원처럼 일하는 개발 환경을 설계했습니다"_

---

## 이야기 구조 (스토리라인)

기존 1,2페이지가 **"무엇을 만들었냐"** 였다면,  
3페이지는 **"어떻게 만들었냐 — 개발 방식 자체를 설계한 이야기"** 입니다.

```
[문제]
AI 코딩 도구를 쓰면 빠르긴 한데...
→ AI가 프로젝트 맥락을 모르고 엉뚱한 코드를 제안
→ 테스트 없이 진행하면 어느 순간 무너짐
→ 팀원들이 각자 다른 방식으로 AI를 사용 → 일관성 부재

[해결 방향]
AI가 혼자 날뛰지 않도록 "개발 환경 자체"를 설계
→ AI에게 맥락을 주고 (컨텍스트 엔지니어링)
→ AI 행동에 가드레일을 달고 (하네스)
→ 사람이 핵심 지점에서 검토·승인 (Human-in-the-Loop)

[결과]
6단계 AI 네이티브 엔지니어링 구조로 프로젝트 완성
```

## 본문 텍스트 초안

### 도입 (왼쪽 상단 or 상단 배너)

> "4명이 AI 코딩 도구를 쓰며 개발했지만, AI가 팀 전체의 맥락을 모른다는 게 문제였습니다.  
> 요구사항은 Clean Architecture 4개 레이어로 설계하고,  
> AI에게 프로젝트를 이해시키고, AI 행동을 제어하는 **환경 자체를 설계**했습니다."

---

### 섹션 1 — 6단계 AI 네이티브 엔지니어링 구조

**[사진 1: 6단계 구조 다이어그램]**  
→ 아래 텍스트를 깔끔한 플로우 차트로 시각화

```
1단계  Instructions   AI가 이 프로젝트에서 지켜야 할 규칙
         .github/instructions/{backend,frontend,rag,ai-model}.instructions.md

2단계  Prompts        영역별 AI 역할과 출력 형식 정의
         .github/prompts/{backend,frontend,rag,ai-model}.prompt.md

3단계  Agents         자율 실행 에이전트 8개 (개발용 4 + TDD용 4)
         .github/agents/{backend,frontend,rag,ai-model,TDD-*}.agent.md

4단계  Context        AI가 작업 전 반드시 파악하는 프로젝트 맥락
         CLAUDE.md / docs/context-packet.md / docs/requirements.md

5단계  TDD            테스트 먼저 정의 → Red→Green→Refactor
         tests/test_{backend,frontend,rag,ai_model}.py

6단계  Integration    배포 전 통합 검증 자동화
         src/todo/manager.py / docs/test-report.md
```

### 섹션 2 — 핵심 3가지 요소 (카드 3개)

#### 카드 1: 하네스 엔지니어링 (Harness)
**[사진 2: .claude/settings.json 코드 스크린샷]**

> AI가 `rm -rf`, `git push --force` 같은 위험 명령을 실행하려 할 때  
> 자동으로 차단하고 사람에게 알림을 보냅니다.  
> 커스텀 슬래시 명령어(`/test`, `/validate`, `/deploy`)로  
> 테스트·검증·배포를 표준화했습니다.

#### 카드 2: 컨텍스트 엔지니어링 (Context)
**[사진 3: CLAUDE.md Few-shot 예시 스크린샷]**

> AI에게 단순히 "코드 짜줘"가 아니라  
> 프로젝트 아키텍처, 금지 패턴, 올바른 대응 예시(Few-shot)를 주입했습니다.  
> "치료" 단어 필터 요청 시 금지어 삭제 대신 정규식 수정을 선택하는 것처럼  
> AI가 의료법을 고려해 행동하도록 설계했습니다.

#### 카드 3: Human-in-the-Loop (HITL)
**[사진 4: HITL 체크포인트 표 or 플로우]**

> AI가 단독으로 결정하지 않는 7개 체크포인트를 설계했습니다.  
> 응급 키워드 목록, 금지어 10개, 품질 임계값(한국어 비율 40%)은  
> 모두 사람이 직접 검토·승인한 뒤 시스템에 반영됩니다.

### 섹션 3 — 실제로 달라진 것 (하단 배너)

| 기존 방식 | AI 네이티브 방식 |
|-----------|-----------------|
| AI에게 요청 → 코드 받음 → 직접 검토 | AI가 컨텍스트 파악 후 → 테스트 통과 코드 제안 |
| 팀원마다 다른 프롬프트 | 표준화된 instructions + prompts |
| 배포 전 수동 체크 | `/validate` 7개 항목 자동 실행 |
| AI 실수 발견 후 롤백 | 위험 명령 훅으로 사전 차단 |
